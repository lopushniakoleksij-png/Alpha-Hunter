# P2 public Bitget read-only collector — prospectively captured venue API data

Gate date: **12 October 2026**. Source: [Bitget official V2 USDT-M Get Ticker API](https://www.bitget.com/docs/catalog/classic-contract-market/classic-contract-market), `GET https://api.bitget.com/api/v2/mix/market/ticker?symbol=BTCUSDT&productType=USDT-FUTURES`. This is the public market-data endpoint, **never** an order or account endpoint.

## What has been implemented and executed

- `ops/reviews/p2_bitget_public_quote_capture_v01.py` is a stand-alone, one-shot collector (not imported by live Render server). Only BTCUSDT/ETHUSDT/QUSDT are statically allowlisted; at this gate ONLY BTCUSDT was used. Request URL is constructed from fixed constants, NOT user-provided.
- `urllib.request` makes exactly ONE GET, `ssl.create_default_context()` validates CA and hostname, proxies are disabled and explicitly forbidden by environment checks, redirects are rejected, response body is limited to 64KiB and client timeout to 8 seconds. No Bitget API credentials, Supabase secrets, trading permissions, websockets, scheduler, paper or real order path.
- The collector validates `code == "00000"`, exact single requested `symbol`, bid/ask and bid/ask sizes strictly positive, no crossed market, numeric millisecond exchange timestamp, **maximum exchange quote age 120 seconds** and at most 60 seconds clock-ahead; these apply to the one-shot capture only and never change frozen 35-minute actual position monitoring.
- Preserves exact original public JSON HTTP bytes and their SHA256, raw row hash, endpoint identity, client capture time, exchange timestamp, a self-consistency receipt digest, and explicit `source_signature_verified=false`, `paper_monitoring_proven=false`, `independent_journal_receipt_committed=false`, `real_order_authority=false`.
- `tests/test_p2_bitget_public_quote_capture_v01.py` uses entirely local fake responses, forcing negative cases for symbol injection, missing/crossed/stale books, future time, HTTP errors, changed payload, forbidden runtime secrets/proxy, repeated artifact path (no overwrite), permission claims and scope isolation.

## Scope limitations / required next gate

TLS hostname validation provides confidence that a public HTTPS response was received from the `api.bitget.com` origin under the OS CA trust model, **but Bitget did not cryptographically sign the market data or trade evidence**. A hash or 7-day GitHub artifact does not create an independent production journal, an as-of source fill-minus-exit ledger, an order-specific previous monitoring seal, or a qualified stop/TP observation. Neither these one-time quotes nor a successful health endpoint prove recurring <=35-minute coverage, resolution of known >35-minute lapses, recovery of unprotected legacy fills, win rate or operational profitability.

**Next hard gate:** deploy a separately reviewed **prospective, read-only and source-labelled transport collector** into its own isolated service without touching main; use independently durable, operator-controlled verification keys and source snapshot custody, bind every position's immutable entry/fill/exit ID and quote attempt to an as-of receipt, then demonstrate repeated per-position <=35-minute observations with all residuals classified under actual Supabase outage conditions. Keep R10 admissions halted until scientific prerequisites are genuinely met. No historical backfills, main branch merge, Primary Hourly stop/restart, frozen 12s SQL/15s HTTP/35m relaxation or order authority.
