## Proposed topology (requires separate explicit approval)

1. **Dedicated Render background worker** (one process, no inbound HTTP/health claims); region provisionally Frankfurt; branch must be new isolated pinned-reviewed successor source/ref, NOT production `main` or inert P2 branch; `autoDeploy=off`, `numInstances=1`, no shared environment group or production code imports. A separate independent uptime watcher must check the worker's forward heartbeat; the worker cannot guarantee an alert if it dies. No overlap with the canonical hourly full-universe scanner.
2. **Source read channel:** a purpose-created least-privilege PostgreSQL LOGIN role on the existing Supabase source database, granted SELECT only on precisely approved paper orders, entry fills, exit fills, protection/exit quarantine and canonical identity sources needed for verification. RLS must be tested; no role inheritance from `postgres`, `service_role` or write roles; no BYPASSRLS, DDL, EXECUTE on mutating routines, INSERT/UPDATE/DELETE, or exchange/API credentials. `SET TRANSACTION READ ONLY` helps but is NOT a sufficient privilege boundary. The selected Supabase session/direct endpoint must be proven to support a single `REPEATABLE READ READ ONLY` transaction under its real pooler, with checked statement timeouts, indexes and bounded query cost. No new source table, function or migration until separately approved.
3. **Actual source completeness:** within ONE authenticated source read transaction, capture all cohort modeled orders, entry fills and exit fills, deterministic row IDs and quantities, as-of source clock and transaction/snapshot identity, row counts, bounded per-table watermarks, invalid/future/partial-row checks, and exact fill-minus-exit positive residuals with stable manifest SHA256. Capture the physical transaction outcome and DB server identity; a purported `complete=true`, string snapshot ID, SQL digest or current managed view alone is NOT source authentication. Persist raw per-row linkage in a separately access-controlled custody store. A failed or incomplete source read must output `INVENTORY_UNKNOWN`; it cannot assert zero positions.
4. **Position classification:** EVERY positive residual, across legacy/R8/R9/R10 including partial fills, is explicitly `MANAGED_WITH_STOP_TP`, `QUARANTINED_NOT_CLOSED`, or `UNPROTECTED_INCIDENT`, bound to that as-of manifest. Never erase NMR; never treat quarantine as proof of exit or protection. Only the managed subset can be tested for qualified forward monitoring, while remaining incidents stay fail-visible and block all-cohort safety claims.
5. **Market data:** for each *managed* paper order, capture contemporaneous Bitget USDT-M public ticker/book with fixed TLS-verified hostname, GET endpoint and `productType=USDT-FUTURES`; approved symbol identity, transport request ID, response timestamp, original response bytes digest, positive/non-crossed price and size, clock skew and freshness. Bind the exact quote source to the monitored order, stop/target state, source manifest, observation time and prior sealed receipt. TLS authenticates a connection, NOT Bitget-signed prices; a price quote does NOT prove future executable exit depth or modeled stop/TP fill. No trade, cancellation, credentialed account or full-universe scan endpoints.
6. **Separate durable custody:** a dedicated **paid, persistent** independent append-only PostgreSQL (or independently reviewed equivalent) with distinct administrative domain, restricted INSERT-only producer, reader/verifier and delivery identities, immutable event IDs, receipt hash chain / HMAC or signed append proof with persistent rotated keys, retention/backups, fail-closed idempotency, backup restore test, and evidence of durable commit before locally accepting a receipt. This must not share the Supabase analytics persistence failure path. A second provider/region failure domain or verified outage-independent sentinel is preferred; two databases within one provider are not proof against provider-wide outages.
7. **Alert and proof channel:** independently durable outbox events for `INVENTORY_UNKNOWN`, `SOURCE_LABEL_UNKNOWN`, `QUOTE_STALE`, `POSITION_RECEIPT_MISSING`, `35M_BREACH`, `INDEPENDENT_JOURNAL_DOWN`, `COLLECTOR_DEAD`, `UNPROTECTED_RESIDUAL` and changed quarantine. An independently monitored dispatcher must send through a separately approved channel (e.g. an authorised email/notification provider) and record provider acceptance plus confirmed recipient/test-channel delivery. `ENQUEUED`, `SENT` and `DELIVERED` are three different states; never print DELIVERED on send attempt alone. External dead-man/heartbeat monitoring must alert when *both collector and journal* are unavailable. Deduplicate pre-existing static incidents, especially 21 quarantined and NMR, while escalating material changes; never flood unchanged alerts.

## Cadence proposal and exact science gate

- **Engineering target (not a new R10 rule):** attempt a scan-independent as-of source read and per-managed-position quote/receipt every **5 minutes** with jitter, bounded timeouts, rate limits and single-instance lease; size/rate must be tested for actual Supabase pressure before approving. An error or slow query is evidence failure, not permission to add traffic, extend a production timeout or postpone the original scan. No overlapping second worker.
- **Warning target:** receipt age >=20 minutes or a missed 5-minute cycle; **urgent prebreach** at >=30 minutes; **breach** when the elapsed time between consecutive *independently qualified actual* per-position observations exceeds 2,100 seconds. Neither proposal relaxes the hard 35-minute bound. Check exact inclusivity: 35:00 allowed, 35:01 rejected. A scan timestamp, attempt row without provenance, last trade/fill clock, an outbox delivery time or a synthetic CI receipt MUST NOT substitute for a qualified observation.
- **Bootstrap:** first independent capture has `NO_PRIOR_SEALED_OBSERVATION`; prospectively start the chain, never certify pre-start monitoring. A closed or disappeared position remains evidence-unknown unless source fill/exits/disposition are independently authenticated. Empty inventory still requires attested complete source snapshot.
- **Unknown/outage:** on Supabase read failure, retain last separately sealed manifest for diagnostic *watch only* and alert stale inventory; never claim the last manifest is a current all-cohort authoritative inventory. On Bitget failure, emit `QUOTE_UNVERIFIED`. On journal failure, no new receipt may qualify. On outage of source plus journal, external independent dead-man monitor must alert. Do not backdate observations during recovery. Freeze a failed prospective episode as fail, even if a later cycle succeeds.
- **Pre-approval prospective test plan:** distinct shadow-only successor cohort, no R10 mixing. At least **72 consecutive hours** of independently captured, verifiable per-position forward data proposed as an operational *qualification window*, including one forced primary Supabase timeout, venue timeout/unreachable, independent journal outage, worker restart, replay/concurrent runs, abnormal clock and both-journal-and-worker interruption. The 72-hour operational window is a REVIEW proposal, NOT a change to the frozen scientific 30-day / 100-trade requirement. All managed positions active during the window must maintain qualified <=35-minute gaps, and every unprotected/quarantined residual must remain visible with incident disposition. Failure injections must generate independently delivered and acknowledged alerts. Any >35-minute gap or lost/unverifiable alarm = **NO-GO**, require a newly approved forward pilot window, never rewrite its records.
