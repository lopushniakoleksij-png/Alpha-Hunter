## Positive controls that should be preserved
- A single four-section navigation (Overview, Research, Paper Results, System) and visible active-tab indication.
- Seven synthetic Chromium viewport widths **320, 375, 390, 430, 768, 1280, 1920px**; synthetic Chromium/WebKit axe WCAG A/AA checks across normal and incomplete-source routes.
- 44px target tests for important research/nav controls; mobile expandable research cards; desktop table; filtering, sorting and numeric exact-value disclosures.
- Distinct warnings for incomplete/publishing/transport-outage states. **Never** substitute prior archived scans for a current signal.
- Strict read-only browser role, separate protected scanner, real-order permission disabled, historic results not represented as live profits.
- Clear focus-visible outline, reduced-motion CSS, role/status labels, and reasonably high contrast in sampled dark-mode token pairs. These strengths do not establish full WCAG conformance.

## Commercial/design scorecard (qualitative, **not measured user research**)
- **Visual language:** coherent, professional dark-terminal base; overloaded error screen and raw Unicode iconography remain.
- **Mobile responsiveness:** substantial tested foundation; actual deployment and true iPhone acceptance incomplete.
- **Research information architecture:** clear separation by tab, but too much internal/scientific jargon for first-time commercial viewers.
- **Accessibility:** synthetic tests PASS, real assistive-tech acceptance UNKNOWN.
- **Performance/availability:** no current quantified frontend budgets; real database-dependent page availability remains impaired/unproven.
- **Buyer/investor readiness:** planning materials exist, but production risk, public/private account boundary and independently evidenced assets remain blockers.

4. **P1 performance** — remove public product-demo dependency on live database, measure actual TTFB and CWV under normal/outage modes, maintain strict fail-closed signals.
5. **P1 real-device acceptance** — manually inspect actual iPhone and desktop at exact release SHA with screenshots, VoiceOver, dynamic type, keyboard, orientation, slow 5G, 200–400% zoom and recovery transitions.
6. **P1 separate web-only deployment** — review, owner approval, explicit rollback plan and proof live web SHA matches tested SHA; keep main branch and protected hourly scanner untouched.
7. **P2 commercial finish** — reviewed About/Product/Evidence, legal/licence/third-party source status, investor demonstration and optional asset-sale package. No price/revenue/return claims without dated proof.
