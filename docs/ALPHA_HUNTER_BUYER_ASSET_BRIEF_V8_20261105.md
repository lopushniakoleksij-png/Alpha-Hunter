# ALPHA HUNTER — POTENTIAL SOFTWARE / IP ASSET SALE BRIEF

**Status:** Internal buyer-readiness draft, 5 November 2026. **Not** a sale listing, public offer, negotiated valuation, guarantee of IP ownership/transferability or authorization to disclose private records.

## What may be offered, subject to diligence

A potential asset buyer could assess Alpha Hunter as an **existing research-software codebase and product prototype**, including the V8 market intelligence frontend, a Flask-based application, paper/shadow research components, operational tests and documentation, if the seller establishes ownership and transfer rights.

**Product boundary:** Evidence-first research, source diagnostics, and paper simulations. **No real exchange-order authority, independently certified profitability or promise of customer/revenue transfer.**

## Diligence schedule

| Category | Candidate assets / scope | Transfer gate |

| Source code | GitHub repository, frontend branch `design/v8-frontend-20261105`, supporting Flask app and research logic | Independent IP rights and third-party licence review; establish exactly which components are seller-owned |

| Automation / scanner | Protected hourly process and monitoring | Explicit controlled handover plan, rollback and uninterrupted research continuity; never silently transfer running credentials |

## Minimum reproducible buyer demonstration

1. An **offline synthetic** V8 demo shows Overview / Research / Paper Results / System at tested mobile and desktop widths; investor/buyer sees clear `SYNTHETIC DEMO` labelling.
2. Search, research filters, sorting, responsive cards, provenance messages, source-unavailable recovery and copy-view-link work.
3. Demo uses **zero** real accounts, trading permissions, production credentials, protected cron or private database records.
4. Attach exact-commit CI results and date. If a run is cancelled, skipped, incomplete or timed out, report **NOT VERIFIED** rather than PASS.
5. Separately disclose unresolved DBA/security sign-off, unknown operations costs, financial evidence, licensing and deployment state.

## Seller-side disclosure policy

Clearly state that:
- The GitHub repository is public, and a public code history alone does **not** prove exclusive transferable rights or a clean licence chain.
- V8 is a **draft web-design branch**, not proof the new experience is deployed to users.
- Paper / modelled performance does not establish live realised P&L, expected returns, customer demand or market valuation.
- External market-data provider rules and personal information may constrain transfer.
- Account credentials, email addresses, API keys, SQL source bodies and user records must never be placed into a public listing or buyer pack.
- Only independently verified revenue, customer, operating-expense and liability figures may be used commercially. Missing evidence must be shown as **UNKNOWN**.

## Recommended sale structure: do not choose yet

**Possible asset sale:** Specific transferable code, branding, documentation and permitted datasets with a carefully negotiated scope. This could reduce dependence on transferring an entire company but does not remove legal/licensing diligence.

**Possible company sale:** Requires verified legal entity, shares, liabilities, contracts, bank/tax records and transfer approvals; none of those is asserted here.

**Possible licence:** License selected IP for research use while retaining control of protected components, subject to enforceable rights and non-conflicting third-party terms.

Do **not** publish an asking price, exclusivity, non-compete, earn-out, support commitment, warranty, escrow deposit or buyer access until separately authorised by the owner and reviewed where necessary.

## Value drivers to substantiate before approaching buyers

- Demonstrably working research workflows and reproducible acceptance tests.
- Clear differentiation against other research terminals based on measured user need.
- Proprietary code and data rights actually owned, clean dependency inventory.
- Retention or paid demand, if independently evidenced.
- Secure operational and support cost profile with verifiable uptime/recovery evidence.
- Small, bounded technical risks rather than unresolved privilege and paper-order safety concerns.

**Unverified valuation:** Not supplied; no figure should be inferred from hypothetical paper returns, development hours or a visually polished web demo.

## Go / no-go checkpoints

**May proceed now (£0):** Frontend polishing, synthetic browser verification, licence/asset inventory, technical documentation, anonymized evidence register and planning a gated demo.

**Requires separate owner permission:** Any external buyer listing, investor introduction, sale negotiation, access grant, transfer of domain/database, new financial obligation or deployment.

**Blocks production promotion:** Independent exact-clone PostgreSQL DBA benchmarking and separate security acceptance remain missing. See [Issue #420](https://github.com/lopushniakoleksij-png/Alpha-Hunter/issues/420). This is a sale-diligence risk and must not be concealed.
